Developer reference / TMDB

API Request Examples

Request headers, URLs, parameters, bodies, and representative responses for the movie app's API helpers.

Examples use placeholders. Replace {{API_KEY}} with the configured TMDB key. Response JSON is illustrative and shortened to relevant fields; it is not a live response.

All app requests use GET. JSON requests send content-type: application/json and accept: application/json; no request body is sent.

Movie ID editor: separate uploads

MovieEditorController / MovieEditorScreen

Open Import > Movie ID editor. Movie Info fetches movie details with credits using the existing TMDB request pattern. All supported movie fields are editable; extra TMDB information is shown in read-only fields and is not uploaded.

Movie Info upload

1. Fetch movie/1726?append_to_response=credits&language=en-US.
2. Edit or preserve the movie text fields:
   title, original_title, overview, tagline, release_date, runtime,
   budget, revenue, status, adult, popularity, vote_average, vote_count,
   poster_path, backdrop_path, optional franchise, genres JSON.
3. Click Upload edited movie and genres.
4. Read/create genre rows (update only changed names), then create/update
   movie row "1726"; verify readback. Never upsert shared genre rows.
   No people or cast/crew credits are uploaded by this tab.

Genres input: [{"id":28,"name":"Action"}] (use [] for no genres).
Boolean input: true or false.
Optional blank inputs: null; franchise blank clears an existing value.

People Info upload

1. Select cast and crew people using separate checkboxes or first-N counts.
   Default counts: 15 cast and 15 crew unique people.
2. Movie "1726" must already exist in Appwrite.
3. Up to 15 people are processed concurrently:
   check people/{TMDB person ID};
   if missing, GET person/{id} and create the full profile;
   if present, preserve it without fetching or rewriting;
   upsert selected cast/crew credits using their stable credit_id;
   verify created profile and selected credit fields/relationships.
4. Success / Already Exists require credit verification.
   Failures report partial writes; Retry selected failed people repairs them.

A person in both lists is processed once; status is shared.
All roles/jobs in selected sections are included.
Movie Info edits do not alter the fetched credits or People Info uploads.

The two tabs use separate upload actions, but overlapping requests and selection edits are disabled while work is active. Shared schema/permission failures stop new work; in-flight operations finish before disposal. No stored rows are deleted. See the Movie ID editor reference and anonymous upload setup.

MCU import: fetch and upload

TmdbMcuImportService / AppwriteMcuImportService

Use the local Marvel seed IDs, not the example movie ID below. Fetch movie details with full credits, then select up to the configured unique cast and crew counts (default 15 each; 0 skips a group). Cast follows TMDB order, crew response order, and all roles/jobs of selected people are retained. Fetch profiles only for selected people missing from Appwrite. Responses below are illustrative; actual credit arrays are not capped.

Upload order and target

Client endpoint = https://nyc.cloud.appwrite.io/v1
Project ID = 6a566f7e0020a7ca4f55
Database ID = 6ae9d8f70009a29b3b5b
No authentication or API key for Appwrite
Administrator temporarily allows Any create/read/update on all five tables

1. Read genres (table genres; row IDs "28" and "878"), create missing rows,
   and update only changed names. Never write their inverse movies links.
   Check selected people by TMDB row ID in table people.
   Reuse existing profiles without rewriting. Fetch full profiles and create
   only missing people; concurrent-create conflicts reuse existing rows.
2. Upsert movie (table 6aeeda38001f609f0ca2; row ID "1726").
3. Upsert cast (table movie_cast; row ID "sample-cast-credit") and
   crew (table movie_crew; row ID "sample-crew-credit").
4. Read back and verify fields and native relationship references.
   Movie genre links use create/update, not repeated relationship upserts.
   Unchanged genre sets are omitted; duplicate genre links fail verification.
   Existing duplicate links are cleared and restored as unique IDs.
   This two-update repair is not atomic; retry a failed partial upload.

Dates: valid YYYY-MM-DD becomes UTC ISO 8601 midnight; empty/null becomes null.
Franchise: optional user value; blank writes null and clears an existing value.
The movie example below assumes the user explicitly entered mcu.
Absent optional fields are not overwritten. Explicit nulls may clear fields.
Store relative image paths, not downloaded images or full image URLs.

genres, movie, and person are native relationship columns, not added string foreign keys. Credits use stable TMDB credit_id row IDs (an intentional deviation from the external guide's random IDs) so a rerun refreshes rather than duplicates them. Legacy random-ID duplicates block the movie with a migration warning. Credits outside the selected import are retained; lowering limits does not delete previous uploads.

No permissions or schema are changed by this screen. Confirm the existing optional franchise String column sized for the supplied value and sufficient budget/revenue integer ranges. Preflight read checks do not prove write permission. Public create/update permits anyone to change the database: revoke those Any grants after importing. Permission/schema failures stop the run; partial uploads remain visible and retryable. See the MCU import reference for actual IDs, guide differences, retries, cancellation, and row-security setup.
